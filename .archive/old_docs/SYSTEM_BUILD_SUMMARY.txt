🎯 HOW IT WORKS

1. REGISTRATION (One-time setup)
   User provides:
   - List of components to monitor
   - Health check functions for each
   - Recovery strategies (actions to take)

2. CONTINUOUS MONITORING
   Every 50-100ms:
   - Call all registered health checks
   - Compare metrics to thresholds
   - Update component health status

3. FAILURE DETECTION
   When component unhealthy for N consecutive checks:
   - Confidence score increases
   - Failure confirmed when confidence = 1.0
   - Record failure timestamp

4. RECOVERY DECISION
   When failure detected:
   - Look up registered recovery strategy
   - Get list of recovery actions
   - Prepare for execution

5. AUTONOMOUS HEALING
   Execute recovery actions:
   - Run each action sequentially or parallel
   - Track execution time
   - Record success/failure
   - Update metrics

6. VALIDATION & RESUME
   After recovery:
   - Check component health again
   - If healthy → resume normal operation
   - If still failing → retry recovery
   - Record success rate

💡 UNIQUE FEATURES

1. CONFIDENCE SCORING
   Failures need N consecutive failures to trigger (reduces noise)
   Default: 3 consecutive failures = confidence 1.0 = detection

2. SMART DEDUPLICATION
   Multiple failures of same component don't trigger multiple alerts
   500ms minimum time between reports

3. AUTO-LEARNING
   System tracks success rate of each recovery action
   Can adjust strategy based on historical success rates

4. COMPREHENSIVE LOGGING
   Every healing cycle logged with:
   - Timestamp
   - Failures detected
   - Actions executed
   - Results and metrics
   - State transitions

5. ZERO CONFIGURATION THRESHOLDS
   System has sensible defaults:
   - Check interval: 100ms
   - Consecutive failures: 3
   - Warning threshold: 60% of critical
   - Action timeout: 5 seconds
